# Portfolio

- Currently include native SOL and fungible tokens only; exclude NFTs and other asset kinds. Request fungibles at the DAS source and enforce the same scope before creating holdings. Older mixed-asset caches are incompatible and must refresh before providing holdings.
- Non-fungible tokens (NFTs) will be included in a separate future milestone.
- Required data: exact amounts, name, symbol, valuation, and rich metadata. Refresh valuations independently of holdings; real-time prices are not required.
- `Portfolio` implements `PortfolioProviding`; RPC owns the selected provider's DAS requests and response decoding. Portfolio depends on the provider-neutral RPC contract.
- DAS is exclusively for portfolio viewing. Use the selected provider's DAS capability for holdings and metadata; behavior without DAS remains deferred.
- Preserve descriptions, website and metadata URLs, media files with MIME/CDN information, typed attributes, collection metadata, creators, asset kinds, token standards, and metadata mutability. Keep provider decoding private and carry shared metadata values unchanged into persisted holdings.
- Omit asset state (supply, authorities, ownership/delegation, royalties, editions, burned status, and compression details) from portfolio holdings and persisted payloads.
- Keep native SOL and Wrapped SOL distinct. Preserve Wrapped SOL's supplied metadata; native SOL retains its own name, symbol, balance, and identity. Reuse the native mint's image from an owned Wrapped SOL holding, or use one same-network `GetAsset` lookup when needed. Preserve valid provider images; a bundled SOL image is only justified when no image source exists. Do not fetch off-chain JSON or media as part of a portfolio refresh.
- Fetch market prices through RPC's interchangeable `PriceProviding` contract. Jupiter is one implementation; its private response is transformed into `Quote`, keyed by mint, with a decimal unit price, currency, retrieval time, and optional 24-hour change. Response decoding and conversion stay private to each provider; shared types use our domain names. Missing quotes mean unknown value, and a missing change means an unknown change; neither is zero.
- Price providers identify their network. Jupiter supplies mainnet USD quotes; do not apply them to devnet balances. Retrieval time is not the underlying market-update time. Currency conversion remains deferred.
- Deduplicate price mints and batch within the provider's limits. Jupiter sends at most fifty mints per request, spaced at twenty requests/minute without a key or forty with a key. Reuse one provider across wallets: its copies and concurrent calls share pacing, but separate instances and devices do not. This local budget cannot guarantee availability under an organisation-wide quota. Waiting is cancellable, idle time does not accumulate burst capacity, and HTTP `429` errors surface without retrying. Pacing requests does not schedule periodic refreshes.
- Inject an optional same-network `PriceProviding` into `Portfolio(rpc:prices:)`. Full refreshes use that provider's quotes for valuations; without one, DAS prices remain available and price-only refreshes report a missing-provider error.
- Use `priceUpdates(for:)` to revalue cached holdings without querying DAS. It requires existing holdings, preserves their amounts, metadata, indexing slot, and `fetchedAt`, and stores quote retrieval times in each valuation's `fetchedAt`. Native SOL and Wrapped SOL share a quote mint while remaining separate holdings. Missing quotes clear the corresponding valuation; totals that cannot be represented exactly by `Decimal` remain unknown.
- Ordinary `updates(for:)` reads reuse data younger than five minutes. Check holdings and independent price ages separately; stale prices alone do not trigger DAS requests. A successful price lookup updates `pricesFetchedAt` even when quotes are unavailable, while each valuation retains its own quote retrieval time. Older caches without `pricesFetchedAt` require a price lookup when a price provider is configured.
- Opening the portfolio view and pull-to-refresh request `.reload`, bypassing cache age while sharing in-flight work and provider pacing. App lifecycle wiring belongs to the app coordinator; the framework does not run periodic polling.
- The internal app `PortfolioCoordinator` exposes observable `update` state, `observe(for:isActive:)` for a view task keyed by wallet and scene activity, and `refresh()` for pull-to-refresh. Cancelling the view task, backgrounding, or changing wallets cancels its consumers; stale sessions cannot publish into the replacement. Backgrounding retains holdings, while changing or clearing selection clears the preceding wallet's display. Subscription failures remain visible without automatic reconnection; explicit refresh still works while the view is active. Overlapping manual refreshes share one operation. View integration remains separate from this coordinator.
- `observations(for:)` shows cached state, establishes confirmed subscriptions, then reloads holdings. RPC's interchangeable `AccountChangeProviding` watches SOL and wallet-owned SPL Token and Token-2022 accounts, including newly created token accounts. `Portfolio(rpc:prices:changes:)` uses the RPC client's subscription capability by default or an injected same-network provider. Share one connection per wallet; cancel the consuming task when observation is no longer needed. The final consumer leaving or wallet removal closes the connection.
- Confirmed changes invalidate cache freshness immediately and coalesce for two seconds before a DAS refresh. Preserve existing holdings until every page's indexing watermark reaches the latest observed slot. Successful responses with an outdated or missing watermark receive at most three reads per reconciliation cycle, two seconds apart; persistent lag surfaces an indexing error and leaves freshness invalidated. Request failures receive no automatic retries. Subscription failures retain cached holdings, report the error, and end observation without reconnecting automatically.
- Await `updates(for:policy:)` or `priceUpdates(for:policy:)` to register a consumer. Fresh cached data emits one ready state; required network work emits cached state first, then its result. Registration completes before the stream returns.
- Each new observation consumer requests a reload or joins one already in progress, sharing the existing wallet connection.
- Order updates with increasing revisions shared across a provider instance's streams. Preserve revisions when forwarding or replaying results; retain a cached snapshot's original revision. Merge holdings and status independently so clock corrections or delayed results cannot discard newer balances or errors.
- Persist snapshots by wallet and network. Reuse existing data before refreshing; a missing snapshot is distinct from a successfully empty wallet.
- Replace stored holdings only after all pages, required metadata lookups, and configured price requests succeed. Fetch failures and cancellation preserve the preceding snapshot and its retrieval times. Storage failures expose the fresh snapshot alongside the error.
- Share concurrent refreshes without sharing a consumer's stream. A full refresh supersedes pending price-only work and satisfies both sets of consumers. Removing wallet data cancels its refresh and prevents obsolete results from restoring the cache.
- Keep metadata and prices optional, balances exact, native SOL distinct, and incomplete valuations explicit.
- When adding currency support, revisit `Amount` so asset and balance displays follow the device's locale and currency settings.
